Each notebook runs the full pipeline for one region: data cleaning, feature engineering,
model training and comparison, evaluation, and forecasting.

## Objective 1 — Revenue Forecasting (Completed)

- **Regions:** Bahrain (AFS, AUB), Oman (ABO, SOH), Egypt, UAE
- **Pipeline (per notebook):**
  - Data cleaning — duplicate-date resolution, outage detection, missing-day imputation
  - Feature engineering — lag and rolling-window features, day-of-week and holiday flags,
    and Hijri-calendar indicators (Ramadan, Eid) to capture Islamic-calendar seasonality
  - Modelling — Linear Regression (baseline), Random Forest, Gradient Boosting, XGBoost
  - Evaluation — MAPE, MAE, RMSE
  - Forecasting — recursive daily forecast with visualisation
- **Result:** MAPE of 6–11% across regions

## Objective 2 — Merchant Value Classification (Completed)

- **Regions:** Bahrain (AFS, AUB), Oman (ABO, SOH), Egypt, UAE
- **Pipeline (per notebook):**
  - Data cleaning — deduplication, missing-value handling, merchant record consolidation
  - Feature engineering — merchant age from onboarding date, early-life (first 6 months)
    transaction behaviour, business type encoding
  - Labelling — value-tier label (Low / Medium / High) derived from later transaction
    volume, using a fixed later-period label window to avoid data leakage
  - Class imbalance handling — SMOTE applied within cross-validation folds
  - Modelling — Logistic Regression (baseline), Random Forest, Gradient Boosting, XGBoost,
    CatBoost
  - Evaluation — Accuracy, Precision, Recall, F1-score, AUC-ROC
- **Result:** Best-performing model varied by region; tree-based ensembles consistently
  outperformed the logistic regression baseline
